# 真机测试指引 —— 去畸变自测页（UVDoc）

> 目标：在**真机**上量出 UVDoc 网格模型的实际耗时，并用肉眼确认「校正前后」的效果。
> 这一页只在 **Debug** 构建里存在，**不需要模拟器**。
> 背景数字（Mac M5 Pro，FP16 ANE 中位 **2.28 ms**）只是指示值——**真机以本页数字为准**。

## 一、准备（一次性）

1. iPhone（iOS **17+**）用数据线连上 Mac，手机上点「信任此电脑」。
2. Mac 上装好 Xcode（本仓用 Xcode 27 / iOS 17 部署目标）。
3. 签名：打开工程后选中 `DDScanner` target → **Signing & Capabilities** → 勾
   *Automatically manage signing* → Team 选你自己的 Apple ID（免费账号够用）。

## 二、构建到手机

```bash
cd <仓库路径>                 # 维护者合入 main 后，这里就是 main 的检出
open DDScanner.xcodeproj
```

1. Xcode 左上：Scheme 选 **DDScanner**（不是 DDScannerContractTests）。
2. 设备目标选你那台 **iPhone**（不要选任何 Simulator）。
3. **⌘R** 运行。首次安装需在 iPhone 设置 → 通用 → VPN与设备管理 里信任该开发者证书。

## 三、打开自测页

首页右上角有一个**心电图图标**（`waveform.path.ecg`，仅在 Debug 构建出现）→ 点它。

页面会自动跑一次（检测 + 约 1–3 秒推理），也可以点右上角「重跑」再来一次。

**批 8 起页面按阶段展示**：原图 → 检测框叠加 → 裁切+透视矫正后 → 去畸变后，每阶段单独计时。
先看 ①②（检测对不对），再看 ③（透视矫正/裁切），最后看 ④（去畸变）。

**管线在后台线程执行**：页面显示「载入图片 / 检测文档边界 / 透视矫正 + 裁切 / 预处理 / 推理 n/30 /
全分辨率重采样」，界面不会被占住；重跑、换图或离开页面会取消上一个任务（取消后不回填过期结果）。

## 三之二、用你自己的照片测

1. 右上角点「**选照片**」（`PhotosPicker`，系统进程外选择器，**不会弹相册权限**）。
2. 选一张**拍歪的纸 / 书页**（越明显的弯曲越好看效果）。
3. 等它跑完（内置样例约 1–3 秒，照片更大时更久）→ 看**三个数字**（预处理 / 推理 median / 全分辨率重采样）与**对比图**。

细节：

- 选中的照片与内置样例走**完全同一条管线**，只是图像来源不同。
- 读入用 ImageIO，**最长边限 4032px**（超出按比例降采样），避免 12MP 整图全解码 OOM；页面「载入后尺寸」会写明是否被降采样。
- 照片的 EXIF 方向会被摆正，竖拍照片不会侧躺。
- 「重跑」重跑**当前来源**（选过照片就继续跑那张，没选就回到内置样例）。
- **重采样耗时随分辨率涨**：内置样例是 1102×1802，换 12MP 照片（4032×3024）后这一步会明显变长，属预期。
- **检测不到文档**（背景太杂 / 纸张与背景对比低）时页面「检测状态」会写「未检测到文档（已回退：整帧直接去畸变）」，
  此时 ② 直接显示原图（无框）、③ 显示原图（未裁切）、④ 对**整帧**去畸变（批 3 的旧行为）。**不崩、不空白**。

## 四、页面上读什么

| 行 | 含义 | 怎么看 |
|---|---|---|
| 模型状态 | 是否装载成功 | 应显示「已装载 UVDocGrid_fp16（computeUnits=all）」；显示红色「模型不可用：…」= 资源没打进包（**不崩**，属降级路径） |
| 算力（MLComputeUnits） | 请求的算力单元 | `all` 表示允许走 ANE；若 median 明显偏大，可对比 `cpuOnly`（需改装配参数，非本批范围） |
| 设备 / 系统 | 机型标识 + 系统版本 | 截图回报时**必须有这一行** |
| 图像来源 | 内置样例 / 相册照片 | 对账用：确认这一轮跑的是哪张图 |
| 源图尺寸 | 源图像素尺寸（应用 EXIF 方向后） | 决定重采样耗时的量级（1102×1802 vs 4032×3024 差别很大） |
| 载入后尺寸 | 实际读入位图尺寸 | 出现「源图最长边 > 4032px，已按比例降采样」= 触发了内存保护 |
| 载入耗时 | ImageIO 建源 + 降采样解码 | 一般几十到几百 ms；异常大说明图很大或 iCloud 现拉 |
| **检测状态** | Vision 是否找到文档边角 | 「已检测到文档（置信度 …）」= 正常；橙色「未检测到文档（已回退：整帧直接去畸变）」= 走降级路径 |
| 裁切结果 | 透视矫正后的输出尺寸 | 正常应是文档本身的像素尺寸；显示「未裁切」或「矫正失败（已回退整帧）」= 走了降级路径 |
| 输入尺寸 / 输出网格 | 模型契约 | 应为 `488×712` / `31×45`（对不上说明产物与代码不同步） |
| **推理 min / median / max** | 30 次推理的耗时分布（ms） | **median 是主指标**；min 与 median 差距大 = 有抖动 |
| **阶段进度** | 当前在跑哪一步（载入/检测/矫正/预处理/推理 n:N/重采样） | 推理逐次回报 n/N；界面全程可响应（不再卡死） |
| 单次均耗时（含首跑） | 30 次总耗时 ÷ 30 | 含首次预热，会略高于 median |
| 预处理（缩放到输入） | 图像 → 488×712 RGB Float32 | 与图像来源无关（两种来源都缩到同一尺寸），只为参考 |
| 全分辨率重采样 | Swift 侧 Float32 去畸变 | 这是替换掉「模型内 FP16 重采样」的那一步，量级应在几十 ms 内 |
| 分阶段对比 ① | 原图（弯曲书页 / 名片） | 看原始拍摄状态 |
| 分阶段对比 ② | 检测框叠加 | 绿框应贴住纸张四边；歪斜/未贴住 = 检测不准 |
| 分阶段对比 ③ | 裁切 + 透视矫正后 | 纸张应被抠成**正面矩形**、占满画面、行列与画布轴平行 |
| 分阶段对比 ④ | 去畸变后 | 在 ③ 的基础上表格线应变直、行距均匀 |

## 五、判读与回报

1. **成绩数字**：回报「检测耗时 + 矫正耗时 + 推理 median / min / max（ms）」+「机型 + iOS 版本」+「computeUnits」。
2. **效果**：按阶段回答 —— ② 绿框是否贴住四边；③ 是否抠成正面矩形、是否摆正；
   ④ 在 ③ 之上是否更平整（表格线变直 / 行距均匀）。仍弯曲 / 波浪 / 边缘被拉伸截断 = 不达标，请截图。
3. **稳定性**：连点几次「重跑」，median 是否稳定（±20% 以内算稳定）。
4. **回报方式**：直接截整页图（含上表所有行与四张阶段图）发给维护者即可。

## 六、这是本批**不**包含的东西

- 没有相机、拍摄、四角微调：自测页的来源是内置合成样张（`Resources/DevSampleDocument.jpg`，
  程序生成的弯曲书页，**不含任何个人信息**）或相册选的照片。**像素前段（检测 → 透视矫正 → 裁切）
  批 8 已接入本页**；`ScanPipeline` 的帧几何入口仍待接线。
- 选中的照片只在**内存**里用于本次自测，不落盘、不上传。
- 批 8 之前，直线透视畸变不由本页处理；现在它由 ③ 这一步负责（Core 出单应，Vision 层成像）。
- 自测页不做 UI 打磨，够用就行。

## 七、降级路径（可选验证）

四条路径都必须**只显示原因、App 不崩、页面其余部分照常**：

| 情形 | 页面显示 |
|---|---|
| 模型缺失（把 `Models/` 从工程资源里去掉再构建） | 「模型不可用：bundle 内找不到 UVDocGrid_fp16.mlmodelc / .mlpackage（是否漏加 Models/ 资源）」 |
| 没选照片 | 不受影响——照常跑内置样例 |
| 相册条目取不到数据（iCloud 未下载完 / 条目失效） | 「读取所选照片失败：相册条目取不到图片数据…」 |
| 图片损坏 / 读不出（如选了非图片或半截文件） | 「读取所选照片失败：无法识别的图片格式…」或「…图片解码失败…」 |

模型缺失那条在 macOS 侧有自动化测试守着：
`swift test --package-path Sources/DDScannerDewarp`（用例「模型缺失时抛 modelUnavailable」）。
